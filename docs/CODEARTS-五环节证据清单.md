# CodeArts 五环节证据清单

> 作用：证明项目是用 CodeArts 代码智能体开发的，不是只把 GitHub 代码导入后原样提交。
> 赛道 1 要的是“开发过程证据”，不是 CodeArts 在运行时参与业务。

## 一、为什么必须有

- 赛道 1 硬性要求：CodeArts 代码智能体为必选；
- 需要五环节证据：需求理解 → 代码生成 → 项目构建 → 问题修复 → 部署上线；
- 代码可以从 GitHub 导入，但**导入本身不算 CodeArts 智能体使用证据**；
- 没有这组证据，作品可能被判不合规，或在“开发过程/华为云使用”项大幅失分。

## 二、最小操作路径

1. 在 CodeArts 里新建/导入项目，源选 GitHub 仓库；
2. 打开 CodeArts 代码智能体；
3. 依次完成下面 5 个真实小任务；
4. 每个任务保留：对话截图、代码 diff/提交、构建或测试日志、部署 URL；
5. 截图存到 `docs/codearts/01-需求理解.png` … `05-部署上线.png`。

> 不需要让智能体从零重写整个项目。让它做 5 个真实、可验证的小改动即可。

## 三、五环节提示词

```text

3）如果要增加“AI 重排失败自动回退”，需要改哪些文件；
4）列出 3 个可验证的验收点。
不要改代码，只输出分析。
```

## 四、证据形式（截图不是唯一形式）

赛题要的是**可核验的五环节证据**，不是固定文件格式。以下任一组合同样有效：

- CodeArts 智能体对话导出 / 录屏；
- 每一步的 commit hash + diff；
- CodeArts 构建日志 / 测试日志；
- 部署记录 + 公网 URL；
- 截图（最直观，推荐保留）。

> 保险做法：至少保留 1 组截图或录屏，再附 commit / 构建 / 部署记录。不要 P 图。

## 五、证据截图规范

每张截图尽量包含：

- CodeArts 项目名；
- 智能体对话内容；
- 时间/运行记录；
- 代码 diff 或构建日志；
- 部署环节包含公网 URL。

不要 P 图、不要补造对话；评委可能会对照提交记录和构建日志。

## 六、最小提交材料

```text
docs/codearts/
  01-需求理解.png
  02-代码生成.png
  03-项目构建.png
  04-问题修复.png
  05-部署上线.png
```

再加一段 200 字说明：每张图对应哪个环节、产生了什么真实结果。

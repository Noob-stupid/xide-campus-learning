# 地图底图、问小习与编排

## 1. 管理员上传楼层底图

入口：`/admin/maps`（管理员登录后左侧「地图」）。

- 支持 PNG / JPG / JPEG / WebP，≤12MB；
- 上传后写入 `data/media/maps/floor_<id>_<hash>.<ext>`；
- `floors.plan_path` 保存相对路径，`/api/floors` 返回 `plan_url`；
- 选座页把底图作为 SVG `<image>` 垫在座位下面，座位仍按 `seats.x/y` 叠加；
- 底图只负责视觉，不改变 A* 路网：导航仍走 `nav_nodes / nav_edges`；
- 删除底图不会删除座位或路网。

参考智座的 `admin/floor-plan` 交互，但本版先做“最小可用的底图上传”，没有把整套拖拽式平面图编辑器搬进来。

## 2. 学习页问小习

入口：页面右下角「小习」浮窗（学习页同样可用）。

接口：`POST /api/learning/ask`，body `{"text": "..."}`。

流程：

```text
学生问题
  → 小习规则解释（极限/导数/时态/递归/语法/单词/概率/线代）
  → 给出一个检查问题
  → 从 contents 中只取 status='approved'
  → 按学科/知识点匹配，返回最多 3 条视频
  → 卡片上可直接播放
```

没有匹配时返回通用建议，不硬凑视频；LLM 未配置时全链路规则可用。

## 3. 编排不是展示页

`services/flow.py` 是真实执行器：

- 预约、结束、交棒上传等动作会 `flow.start` 创建 run；
- 每个 `flow.step` 真正执行节点函数，把输入/输出/状态/耗时写入 `workflow_steps`；
- 节点失败会把 run 标为 failed 并抛出，页面可以回放到失败节点；
- `/workflow` 只是读取这些 run/step 的回放界面，不是另外画一张假流程图。

当前是轻量串行引擎，没有独立队列、重试调度和跨进程 worker；这些属于云上生产化范围。

## 4. 硬件沙盒联调

已用 `dsh-breadboard` 的 `zhizuo-sensor` 协议联调：

```text
POST /api/sensor/device/register
GET  /api/sensor/device_config?device_id=...
POST /api/sensor/report
```

两块 PIR 都遮挡时 `seats` 的 `live_status` 变为 `occupied`；连续两次无人后释放。服务端返回 `{code,message,data}` 信封，硬件沙盒可直接识别。

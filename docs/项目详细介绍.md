## 1. 背景与问题

高校图书馆、自习室每天都在发生三件互相割裂的事：

1. **找座难**：学生不知道哪层、哪个区域有空位；预约、签到、离座释放靠人工或分散的系统。
2. **学习内容与学习行为脱节**：学生看完一条学习视频，和“我今天在哪个座位、学了多久、卡在哪”没有关系；平台推荐的是“猜你喜欢”，不是“你此刻最需要的”。
3. **学习内容缺少合规审核**：学生/教师上传的学习视频如果直接分发，存在合规、质量、版权与隐私风险；全量逐帧人工审核成本高，纯 AI 自动判定又不可信。

「习得」把这三件事收束到**同一个对象**上：**一次学习场次（Study Session）**。

> 座位是物理锚点，学习是连续线程，工作流是总指挥。

## 2. 产品定位与创意

### 2.1 不是选座系统，也不是视频站

- 不是“选座 + 视频审核 + 工作流”三个模块并排；
- 而是“一次自习”的完整生命周期服务：
  - 落座前：找座、预约、导航；
  - 落座中：计时、卡住了辅导、学习计划；
  - 离座后：结束/到期触发接棒，推送一条已过审学习视频；
  - 内容侧：学生/教师交棒，经过帧级复核后进入接力池。

### 2.2 核心创意：结束即服务

大多数选座系统在“离座”那一刻结束；「习得」把离座当成**下一次学习的开始**。

> 刚结束学习的 10 分钟，是记忆最新鲜、最愿意再看一条 3 分钟视频的窗口。

推送不是信息流，而是**事件驱动的即时学习（just-in-time learning）**：

- 触发：手动结束 / 预约到期（仅已签到场次）；
- 依据：学科、时长、座位区、辅导卡点、历史反馈；
- 内容：只从**已通过 AI + 人工帧级复核**的接力池里选；
- 解释：接棒卡写清“为什么推给你”；
- 反馈：有帮助/没帮助回流，下一次更准。

### 2.3 记忆点

- **交棒 / 接棒**：上传叫交棒，收到推送叫接棒，内容池叫接力池；
- **接棒卡**：像票根/登机牌，带匹配理由与复核签章；
- **一屏帧级复核**：AI 只标疑点，人只拍板可疑帧；
- **离座，不放学**：一句话主张。

## 3. 三个原作品的融合逻辑

融合原则：**不搬皮肤，搬交互；不搬业务外壳，搬能力。**

| 原作品 | 在新项目里的角色 | 只吸收什么 | 明确不搬什么 |
|---|---|---|---|
| 校园创意文化展示站 | 交棒流水线（内容供给侧） | 上传、抽帧、AI 初筛、人工复核、审核状态、播放页、卡片网格 | 轮播、热门榜、点赞/收藏/评论/关注、动态、UP 主主页、整套视频站外壳 |
| 智能选座与导航 | 接棒流水线（空间需求侧） | 座位图交互、多建筑/多楼层（先选地点再选座）、预约卡、A* 导航、AI 推荐理由 | Vue3/Element/Fabric/ECharts 重前端、整套设备/建筑管理后台、室外导航/高德、移动端 App |
| 农技宝任务流 | 两条流水线的引擎 | 1+N 意图路由、澄清循环、苏格拉底教学循环、状态传递、异常兜底 | 农业知识库、作物诊断、超星平台外壳 |

结果：三个作品不是“并排站”，而是同一条学习场次链路上的三个工位：**空间调度 → 学习辅导 → 内容接力**。

## 5. 端到端业务流程

```
【供给侧】
学生/教师交棒 → 上传视频 → 抽帧 → AI 初筛 → 人工一屏帧级复核
  → 通过 → 接力池（只有 approved 能进入）
  → 驳回 → 原因反馈给交棒者

【需求侧】
首页建议 → 找座 → 预约 → A* 导航 → 签到
  → 学习计时 → 卡住了（苏格拉底辅导）→ 推荐视频
  → 手动结束 / 预约到期
  → 接棒工作流：场次上下文 → 候选检索 → 匹配排序 → 推送决策
  → 接棒卡 → 观看 → 有帮助/没帮助
  → 反馈回流 → 下一次更准

【编排】
五条流：学习计划 / 预约履约 / 学习辅导 / 接棒推送 / 交棒审核
```

## 6. 核心功能模块

### 6.1 多建筑 / 多楼层：先选地点，再选座位

- 选座页顶部是两步流程：**① 选择地点**（建筑下拉 + 楼层 Tab）→ **② 选择座位**（座位图）；
- 演示数据：图书馆 2F 静学自习区（48 座）、图书馆 3F 研讨协作区（16 座）、教学楼 A 1F 自习室（15 座），共 79 座；
- 切换楼层自动重载该层座位图、区域标签与路网；预约/导航都带楼层信息；
- 泛化方式：数据模型按 `floor_id` 组织，新增场馆只扩展 seed 数据；
- 专一：所有场馆都服务“学习空间”场景，不做通用场地租赁/活动报名。

### 6.2 座位与预约

- 先选地点（建筑 + 楼层），再进入座位图；
- 座位状态：空闲/已预约/使用中/临时占用/维护；
- 筛选：全部/靠窗/安静/电源；
- 推荐：按偏好 + 历史 + 距离打分，给出理由；
- 预约规则：单次 1–240 分钟、同一用户最多 1 条进行中预约、同座位时段不重叠；
- 并发：本地 `RLock + BEGIN IMMEDIATE`；云上 Redis 锁 + RDS 事务兜底。

### 6.3 A* 室内导航

- 每个楼层独立路网：入口 → 大厅 → 走廊 → 分区过道 → 座位；
- A* 返回路径、距离、步行时间、文字步骤；
- 导航页显示座位/区域，支持从入口到任意座位。

### 6.4 学习场次与辅导

- 签到创建 `study_sessions`，开始计时；
- 学习计划：50 分钟专注 + 10 分钟休息（按历史建议）；
- 「卡住了」：苏格拉底式两轮提问 → 解释 → 检查问题 → 推荐已过审视频；
- 卡点写入场次上下文，供结束后接棒匹配。

### 6.5 交棒与帧级审核

- 上传：mp4/mov/webm，最多 500MB；
- 抽帧：最多 12 帧，按时间均匀；
- AI 初筛：红色占比、亮度、模糊、暗部、文本关键词；
- 人工复核：一屏工作台（视频 + 帧时间轴 + AI 理由 + 四项清单 + 通过/驳回 + 帧级状态）；
- 只有 `approved` 内容进入接力池；
- 帧级审计：每帧 `pending/cleared/flagged`，复核记录带审核员、时间、意见。

### 6.6 接棒推送

- 触发：手动结束 / 预约到期（仅 checked_in）；
- 上下文：学科、时长、座位区、卡点、历史、已看内容；
- 候选：只取 `approved`；
- 打分：主题/知识点/时长/新鲜度/质量；
- 决策：有匹配→接棒卡；无匹配→兜底建议；免打扰→定时；已推→跳过；
- 幂等：一个场次只推一次。

### 6.7 个人学习档案

- 视频站式视觉：封面 + 头像 + 数据栏 + 5 Tab + 卡片网格；
- 头像/封面点击即可上传更换；昵称、学院、学习签名、兴趣方向可编辑；
- 数据栏：学习场次/专注时长/我的交棒/接棒记录/有帮助率；
- Tab：我的场次/我的交棒/接棒记录/学习轨迹/设置；
- 学习名片：可截图分享，不含粉丝/获赞等社交指标；
- 设置页含通知、免打扰、隐私开关。

### 6.8 智能体与工作流

- 全局助手（右侧竖排「小习」）：找座/场次/推荐/卡住了；
- 规则意图路由 + 只读查库；无大模型也能完整跑通；
- 五条工作流的节点图、运行记录、节点日志在 Web 编排页可见。

### 6.9 空间感知（可选）

- `/api/sensor/register`、`/api/sensor/report`；
- 管理端设备模拟器；
- 设备状态只补充“此刻有没有人”，不覆盖预约。

### 6.10 室外导航

- 从校门/当前位置步行到图书馆、教学楼 A；
- 显示距离、步行时间、方位（北/东北/东…）和分步文字指引；
- 未配置高德 Key 时用相对方向示意图；配置 `AMAP_JS_KEY` 后可扩展高德步行路线；
- 提供「在高德地图中打开」手机地图链接；
- 到馆后进入室内导航，继续选楼层/座位。

### 6.11 个人主页编辑

- 点击头像上传新头像，点击封面或「更换封面」上传背景图；
- 「编辑资料」可改昵称、学院、学习签名、兴趣方向；
- 头像同步到侧栏、顶栏；封面同步到个人主页；
- 图片存 `data/media/profiles/`，限制 jpg/png/webp/gif、≤ 8MB。

## 7. 五条工作流

| 流 | 触发 | 节点 |
|---|---|---|
| 学习计划 | 目标输入 | 目标理解 → 拆解任务 → 排期预约 → 提醒 |
| 预约履约 | 确认预约 | 意图约束 → 座位匹配 → 锁座 → RDS 落库 → 导航 → 通知 |
| 学习辅导 | 签到/卡住了 | 签到 → 学习计划 → 专注计时 → 苏格拉底 → 推荐视频 → 结束 |
| 接棒推送 | 结束/到期 | 事件 → 上下文 → 候选检索 → 匹配排序 → 决策 → 推送 |
| 交棒审核 | 上传 | 上传 → 抽帧 → AI 初筛 → 人工帧级复核 → 入池 |

运行记录落 `workflow_runs` / `workflow_steps`，每个节点有 input/output/error/开始结束时间。

## 11. 泛化与专一

### 泛化

- 建筑/楼层/座位/路网均按 `floor_id` 组织，数据驱动；
- 新增场馆/楼层只扩展 seed 数据，API/页面/统计自动适配；
- 工作流引擎与内容匹配不依赖具体楼层；
- 选座页固定“先选地点，再选座位”两步，避免跨层误选。

### 专一

- 场景只做“校园学习空间”，不做通用场地租赁、活动报名、社交平台；
- 内容只做“学习/教学视频”，不做娱乐短视频；
- 辅导只做“卡住了”的即时帮助，不做题库/刷题；
- 个人主页只做学习档案，不做粉丝/获赞/热门。

> 一句话：**底座泛化，场景专一。**

---

## 12. 安全与合规

- 审核：AI 初筛 + 人工帧级复核 + 四项清单（合规/质量/相关性/版权与隐私）；
- 审计：复核记录、帧级状态、工作流节点日志；
- 隐私：不展示他人预约详情；不出现粉丝/社交指标；
- 密钥：`.env` / 云上环境变量，不提交 AK/SK；
- 演示：所有数据为合成/演示数据，不包含真实学生隐私。

## 20. 可选 AI 层（MaaS / OpenAI 兼容）

- 适配器：`services/llm.py`；
- 环境变量：`ZX_LLM_BASE_URL`、`ZX_LLM_API_KEY`、`ZX_LLM_MODEL`；
- 接棒匹配：规则打分后，LLM 在候选内重排并生成一句推荐理由；失败回退规则；
- 辅导：学生答错/部分对时，LLM 生成更小的追问；失败回退规则提示；
- 助手：未知/卡住类意图用 LLM 润色回复；座位号、时间等事实不交给模型改写；
- 未配 Key 时全部规则兜底，应用仍可完整运行；
- 管理后台：`/admin/ai` 可视化添加供应商、设置优先级、测试连接、保存即生效；当前供应商失败自动切下一个。
- 反馈回流：有帮助/没帮助计入内容质量，下一次排序按 0.85–1.15 系数调整。

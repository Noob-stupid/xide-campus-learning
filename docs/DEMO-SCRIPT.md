## 关键话术

**开场：**
> 我们做的不是选座，也不是视频站。我们把一次自习做成一条学习内容的流水线：找座是触发器，学习结束自动生成接棒，AI 只标疑点、人来拍板，通过后回流给下一个学习者。

**接棒卡：**
> 你刚在 A-06 完成 2 小时学习，这条 3 分钟视频讲的正是你卡住的 ε-δ；它已经通过 4 帧人工复核。

**审核台：**
> AI 初筛标红了这一帧“大面积红色”，人工点一下跳到 00:06，发现是重点标记页，清除后通过；整个过程帧级可追溯，不是“全自动”。

**编排：**
> 这不是一次 API 调用：结束事件、场次上下文、候选检索、匹配排序、推送决策，每个节点都有输入输出和耗时；失败会重试，重复触发幂等。

**收口：**
> 座位会空，学习不会。Redis 保证抢座不超卖，RDS 保证每条记录可追溯，OBS 承载视频，CodeArts 把想法变成云上应用。

## 可能被问的问题

**Q：这不就是选座 + 视频审核吗？**
A：不是。视频不是另投的，是这场自习结束后按场次上下文匹配的；审核是 AI 初筛 + 人工帧级拍板；选座是触发器，不是另一个功能。

**Q：为什么需要工作流？**
A：有分支（无匹配/免打扰/已推过）、有等待（人工复核）、有失败重试、有事件触发，不是一次调用能完成的。

**Q：AI 审核准确率多少？**
A：我们不做全自动判定，做的是提高可疑帧召回、降低人工看全片成本；指标是可疑帧召回、人工复核耗时、帧级可追溯率。

**Q：华为云用在哪？**
A：RDS 存记录、Redis 锁座/幂等、OBS 存视频、MaaS 可选做意图/辅导，CodeArts 完成开发部署闭环；证据在 `docs/HUAWEI-CLOUD.md`。
